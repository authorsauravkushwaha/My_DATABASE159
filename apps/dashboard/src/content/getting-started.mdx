# Your first five minutes

Kestrel gives small and growing teams a typed, high-density database workspace: projects for isolation, collections for schemas and secondary B-tree indexes, and a data explorer built for bulk ingestion, O(1) cursor pagination, and streaming NDJSON exports.

## 1. Create an isolated project

Every collection and record lives inside a project, and every project belongs to an organization. Use separate projects for separate applications or environments so schemas, 64-bucket hash shards, and API switches do not collide.

## 2. Shape a collection & secondary indexes

A collection defines the fields every record can contain (up to **128 typed fields** and **16 secondary B-tree indexes**):

```json
{
  "type": "object",
  "properties": {
    "name": { "type": "string" },
    "price": { "type": "number" },
    "in_stock": { "type": "boolean" }
  },
  "required": ["name", "price"],
  "indexes": ["name", "price"],
  "additionalProperties": false
}
```

Unknown fields are rejected before data is stored, keeping records predictable across services and UI clients.

## 3. Bulk-ingest, query via indexes, and stream NDJSON

Use the typed client from browser or server code. Browser apps should talk to a same-origin `/api/` reverse proxy so tokens stay on one origin.

```ts
import { KestrelClient } from '@kestrel/client';

const db = new KestrelClient({ baseUrl: '/api/' });
const session = await db.login({ email, password });
db.setToken(session.access_token);

// Ingest up to 5,000 schema-validated records in a single compressed batch
await db.batchCreateRecords(projectId, 'products', [
  { name: 'Desk lamp', price: 64, in_stock: true },
  { name: 'Studio monitor', price: 249, in_stock: true },
]);

// Push down predicates to secondary B-tree indexes with O(1) cursor pagination
const page = await db.queryRecords(projectId, 'products', {
  filters: [{ field: 'price', op: 'lte', value: 100 }],
  limit: 100,
});
```

For large dataset migrations or backups, stream the entire collection in constant memory using `db.exportRecordsNdjson(projectId, 'products')` or upload newline-delimited JSON with `db.importRecordsNdjson(...)`.

## 4. Hand servers a scoped API key

Browser sessions are short-lived; background jobs and services should authenticate with a project-scoped key instead. Mint one from **Settings → API keys** or straight from the SDK:

```ts
const key = await db.createApiKey(projectId, { name: 'Nightly ingest', role: 'writer', expires_in_days: 90 });
db.setToken(key.api_key); // full secret, returned exactly once
```

`reader` keys can list, query, and export but never write; `writer` keys cover the full data plane but cannot manage projects, organizations, or keys. A key is pinned to one project, cannot outlive its creator's membership, and stops working the moment it is revoked.
